迁移于同日完成，脱敏证据见 [迁移记录](matrix-johor-migration-2026-09-07.json)。迁移前先停止连接器、执行端、Synapse 和 PostgreSQL，再通过 SSH 复制一致性快照。目标首次启动前，5,220 个文件及目录的内容、属主和权限逐项匹配（文件内容使用 SHA-256 校验），4 个镜像 ID 与原部署一致。

- 先续接迁移前的旧会话，确认上下文和去重记录保留，再运行完整联邦验收，包括双向 REST/JSON-RPC、请求箱审批、SSE、取消、离线补收、重启恢复和有限 timeline 补齐。
- 真实 Codex 沿用迁移前的 session；第二轮没有重新提供随机标记，仍准确取回原内容并保持同一 session ID。模型请求由柔佛直接发出，不依赖原服务器代理。验证后已恢复确定性 Agent。
- 交付 CLI 的 `doctor` 返回 ready，跨域 `send` 返回 completed Task 和预期 Artifact。最终 8 个 Matrix 容器运行正常，两个连接器 ready；柔佛原有 4 个 Router 服务的容器 ID、镜像、启动时间、重启次数和健康状态均保持不变。
- 原服务器移除了 8 个 Matrix 容器、1 个专用网络、4 个镜像的 6 个标签、46 条本次构建缓存及部署目录。原有 3 个 Codex verifier 服务的容器 ID、镜像、启动时间、重启次数和健康状态未变，31 条旧构建缓存与原有基础镜像保留。

柔佛保留了经过逐文件校验的迁移前备份：`/opt/agent-router-matrix-lab/state/pre-migration-backup.tar.gz`，仅属主可读写。恢复必须先停下 Matrix 栈，再整体恢复数据库、签名密钥、令牌、连接器状态和运行时会话，不能同时启动两个副本。

## 实测中修正的问题

- 首条任务与远端入房发生竞态：先在发送方的持久 outbox 保存，确认对端已加入后再发布。
- 官方 A2A Card 发现需要独立配置认证 fetch，并保留网关基础路径末尾的斜线。
- input-required 续接时立即更新源 Task 状态，避免客户端误以为仍在等待上一轮输入。
- 未知执行接受结果的取消不能虚报成功。
- 超大结果依然证明执行已被接受；保留映射并返回投递错误，不能变为自动重新执行。
- 严格 TLS 校验需要完整的 CA/叶证书扩展；Codex 容器需安装可信 CA bundle。
- 撤回待批准请求应同时清理请求箱条目。
